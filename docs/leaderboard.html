How to read these numbers

Outcomes are about evidence, not about “model quality” in the abstract

✕Refuted

At least one frozen database state makes the candidate return a different result than the reference query. The state, both result sets and a replay flag are stored in data/evidence/.

One counterexample is enough: a rewrite is wrong if any allowed state breaks it.

✓Preserved

The candidate differs from the reference SQL, and no state in the finite bank broke it. This is not a proof of equivalence — the bank is finite and cannot cover all possible databases.

Read it as “no evidence against on this bank”, never as “correct rewrite”.

–No rewrite

The model returned the reference query unchanged. That is neither a success nor a failure: there was no rewrite to validate.

Unsupported candidates and execution errors are separate outcomes; both are 0 in this release.

ΣWhy checks beat shares

A pass rate hides the counterexample: 335/336 sounds excellent until you see that the one failure is a semantic bug. That is why this table shows refuting checks (35, 13, 3) over executed checks (336), not percentages.

Every check is one executable state; the count is directly auditable in the data.
